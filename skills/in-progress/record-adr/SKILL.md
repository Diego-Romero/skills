# Record an architecture decision

Identify the decision the maintainer made. If they are still weighing options or the reason for the choice is unclear, ask what they decided and why. Use repo evidence to clarify the context and consequences. Let the maintainer supply or confirm the rationale.

Find the repo's ADR directory, naming convention, and template. Read any related ADRs and identify whether the new one supersedes an earlier decision. If the repo has no convention, suggest a location and a short title.

Draft the record with the decision, the context that drove it, and the consequences that matter. Include alternatives only when they explain the choice. Keep implementation steps in the relevant pattern guide or task.

Show the draft and destination for review. After the maintainer confirms, save it and update the ADR index or supersession links if the repo uses them.
